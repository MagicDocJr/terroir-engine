How each was to build for an AI

Three.js (WebGPU)

  • All plain text. I can verify it myself by driving Chrome on your real GPU and taking screenshots.
  • You build the renderer yourself: shadows, reflections and post-processing are assembled by hand, and I hit two engine-specific traps along the way (the order of instancing vs. custom shader code, and reflections re-rendering all shadows).
  • Reflections come from a real mirror render. Lighting has no built-in indirect bounce, so it looks moodier and flatter in the shade.
  • The headless browser sometimes throttles during long capture runs, so automated tests need care.
  • Big plus for the MVP: the Football Manager-style dashboard is plain web UI (React), which is by far the easiest place to build dense tables and charts.

Godot 4.7

  • Also all text (.tscn, .gd, .gdshader). It never needed the editor: the whole scene is built by script, and screenshots and FPS come from a command-line flag.
  • More "free" realism out of the box: indirect bounce light (SSIL), screen-space reflections, MSAA. That's why it looks brighter and more sunlit.
  • One colour-space mistake (vertex colours) took a debug detour. Capture runs open a window on your desktop.
  • A dense data dashboard would have to be built from Godot's UI toolkit, which is much weaker than the web for tables and charts, or run as a separate web app next to it.
